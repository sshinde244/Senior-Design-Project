About this project

Claude + MCP = MCPortal

This workspace demonstrates how Large Language Models can go beyond conversation by connecting to real-world tools and data through the Model Context Protocol.

What is this?

This is a fullstack Node.js application that gives Claude the ability to call external data APIs — not by hard-coding responses, but through a protocol that lets Claude discover and use tools dynamically at runtime.

When you ask "What's the population of Texas?" or "Who directed Inception?", Claude doesn't guess. It calls the appropriate MCP tool, receives live data, and synthesises a real answer.

The result is an AI assistant that is genuinely grounded in current, factual information rather than training-data approximations.

Node.js Express Anthropic SDK Claude Agent SDK MCP (stdio) TMDB API US Census API

How a request flows

1
You type a message The frontend sends your message and conversation history to the Express server via /api/agent.
2
Claude Agent SDK runs The server invokes Claude with access to the selected MCP. Claude decides which tools (if any) to call.
3
MCP subprocess executes The MCP server (a child process) receives tool calls over stdio and fetches live data from external APIs.
4
Claude synthesises the answer Tool results are returned to Claude, which produces a final natural-language response back to you.

01 / 06  ·  Introduction

MCPortal

Large Language Models are powerful reasoning engines — but they're frozen in time, limited to their training data. What if Claude could reach out and look things up?

This project answers that question with a working fullstack application: a chat interface where Claude uses live, external data sources to give you real answers.

02 / 06  ·  The Problem

Why tools matter.

01 LLMs hallucinate specific figures — populations, box-office revenues, cast lists — because they approximate from training data.
02 Training data has a cutoff. Real-world information changes constantly: trending films, census updates, economic indicators.
03 Users need to trust the answers they get. Grounding AI in authoritative APIs builds that trust.
03 / 06  ·  The Solution

Model Context Protocol.

MCP is an open standard that lets Claude discover and call external tools at runtime. Each MCP server exposes a set of typed functions — Claude decides when and how to call them.

→ Claude sees tool definitions (name, description, input schema) and decides autonomously which to invoke.
→ Tool results are fed back into Claude's context, enabling multi-step reasoning over real data.
→ Servers communicate over stdio — a simple, secure, process-level boundary.

Built with modern tools.

Chat API

A simple direct conversation with Claude. No tools, no MCP — useful for general Q&A without needing live data.

POST /api/chat // Request body { "message": "What is the capital of France?", "history": [ // optional { "role": "user", "content": "Hello" }, { "role": "assistant", "content": "Hi! How can I help?" } ] } // Response { "reply": "The capital of France is Paris." }

Agent API

An agentic Claude request where the selected MCP server's tools are available. Claude will call tools as needed and return a synthesised answer.

POST /api/agent // Request body { "message": "What are the top trending movies this week?", "history": [], // optional conversation history "mcpId": "tmdb" // "tmdb" or "census" } // Response { "reply": "This week's top trending movies are...", "selectedMcp": { "id": "tmdb", "label": "TMDB Movies & TV MCP" } }

MCP Configuration

All MCP servers are registered in claude.config.js inside the mcpRegistry object. Each entry defines how to launch the MCP subprocess:

const mcpRegistry = { tmdb: { id: "tmdb", label: "TMDB Movies & TV MCP", command: "node", args: [path.join(__dirname, "tmdb-mcp.js")], env: { ...process.env, TMDB_API_KEY: process.env.TMDB_API_KEY }, }, };
FieldDescription
idUnique identifier used in API requests as mcpId
labelHuman-readable name shown in the UI dropdown
commandExecutable to run (e.g. node, docker)
argsArray of arguments passed to the command
envEnvironment variables available to the subprocess

Adding a New MCP

To add a new MCP server, follow these steps:

1. Create the MCP server file

Write a Node.js script (or any executable) that implements the MCP stdio protocol: handle initialize, tools/list, and tools/call JSON-RPC messages over stdin/stdout.

2. Register it in claude.config.js

mcpRegistry.myNewMcp = { id: "myNewMcp", label: "My New Data Source", command: "node", args: [path.join(__dirname, "my-new-mcp.js")], env: { ...process.env, MY_API_KEY: process.env.MY_API_KEY }, };

3. Restart the server

The new MCP will automatically appear in the dropdown in the Chat page once the server restarts. Claude will have access to all tools it exposes.

  • Tool names must be unique within an MCP server
  • Input schemas must follow JSON Schema format
  • Always pass API keys via env, never hardcode them
  • Keep tool descriptions clear — Claude uses them to decide when to call each tool
